The real test of PRF is step 1: the authenticator answers prf.enabled itself. A browser can support the extension while the authenticator it picks does not.

1 · Create a lab passkey (navigator.credentials.create)

Exactly the parameters of the design: resident key required, user verification required, ES256 then RS256, extensions.prf = {}, a fresh 32-byte user handle. Your authenticator will ask for a gesture. Make two, or five: each one is a separate passkey with its own PRF secret.

2 · Ask it for the PRF bytes (navigator.credentials.get)

The lab's salt goes in as prf.eval.first; 32 bytes come out, after a gesture. Ask twice with the same salt and the bytes are the same. Ask with another salt and they differ. Ask another passkey and they differ. The bytes are shown as a fingerprint (the first 16 hex characters of their SHA-256); tick the box to see them whole.

3 · From the bytes to a lab keyring (HKDF, AES-256-GCM)

With the bytes of the passkey picked above: HKDF-SHA256 with the lab salt and the label sgit-secrets/v1/wrap/<credentialId> gives the wrapping key; the first time, the lab also makes a KEK (32 random bytes) and encrypts a one-entry body under it. Each passkey you run this for adds one wrap of the same KEK to the same lab keyring.

4 · Unlock it again

One gesture with the passkey picked above: bytes, HKDF, unwrap, decrypt. With the KEK forgotten from memory this is the returning flow exactly; with it still in memory the lab checks that the unwrapped KEK is the same one. A second passkey that has a wrap unlocks the same body.
